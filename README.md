# AI City Brain — NovaCity Smart City Command Center

A live, multi-agent digital twin for a fictional city ("NovaCity"): six specialized AI
agents (Traffic, Flood, Emergency, Waste, Energy, Healthcare) plus a central "City
Brain" orchestrator watch a simulated city, react to events on a shared event bus,
and drive a real-time command-center dashboard — all runnable **completely free on a
laptop**, with no Docker, no API keys, and no external services required.

```
Java 21 · Spring Boot 3.5 · Spring Security (JWT) · Spring Data JPA · Flyway
H2 (zero-install) / PostgreSQL (optional) · WebSocket · springdoc-openapi
React 18 · TypeScript · Vite · Tailwind · Leaflet · Recharts
```

## Why this exists

This started from a one-page product brief ("AI City Brain — Intelligent Smart City
Digital Twin") describing a rule-based multi-agent system, a live simulation engine,
and a "what-if" scenario tool. This repository is a genuine, working implementation
of that brief, built end-to-end: real JWT auth with six role-based accounts, a real
scheduled simulation engine, real agent-to-agent coordination through an in-process
event bus, a real WebSocket-pushed dashboard, and a real (optional) LLM integration —
not a mockup or a slide deck.

## Quick start (zero install beyond a JDK + Node)

```bash
# 1. Backend — file-based H2, no Docker, no Postgres, no API keys needed
cd backend
./mvnw spring-boot:run          # or: mvn spring-boot:run
# → http://localhost:8080  (Swagger UI: http://localhost:8080/swagger-ui.html)

# 2. Frontend, in a second terminal
cd frontend
npm install
npm run dev
# → http://localhost:5173
```

Log in with any of the demo accounts below (or use the one-click picker on the login
screen), then open **Simulation → Scenario Presets** and trigger "Heavy Rain" or
"Major Accident" to watch the agents react live.

### Optional: run against real PostgreSQL via Docker

```bash
docker compose up --build
# Backend:  http://localhost:8080
# Frontend: http://localhost:5173
```

Still 100% free — `postgres:16-alpine`, `nginx:1.27-alpine`, and your own build are
the only images involved.

## What's real, what's simulated — read this before demoing

In the spirit of not overclaiming:

| Capability | Status |
|---|---|
| JWT auth, RBAC, password hashing | **Real.** Spring Security, BCrypt, stateless JWT. |
| Six agents + CityBrain orchestrator | **Real.** Independent Spring services reacting to a shared event bus, with real thresholds and real cross-agent coordination (e.g. Flood Agent → Traffic Agent closes roads). |
| Simulation engine | **Real**, but the underlying city data is **synthetic** — NovaCity is a fictional city, and its weather/traffic/power numbers are generated by a bounded random-walk model, not fetched from a live weather or traffic API. |
| WebSocket live updates | **Real.** A native WebSocket endpoint (`/ws/city`) pushes city status, incidents, alerts, and the AI-decision feed as they happen. |
| AI natural-language briefings | **Real**, dual-mode: a deterministic rule-based generator runs by default (free, no key); setting `AI_PROVIDER=llm` + `ANTHROPIC_API_KEY` swaps in genuine Claude-generated text, with automatic fallback to rule-based on any failure. |
| Database persistence | **Real.** Every incident, alert, agent decision, and simulation run is a real row, via Flyway-versioned schema. |
| Interactive map | **Real** Leaflet map with live data; base tiles are free CARTO/OpenStreetMap tiles (attribution required and included). |
| Kafka / Redis | **Not included.** The event bus is a synchronous in-process implementation (`InMemoryEventBus`) behind an `EventBus` interface designed so a Kafka-backed implementation could be swapped in later without touching agent code. This was a deliberate choice for the zero-cost, single-laptop constraint — see `docs/ARCHITECTURE.md`. |
| Multi-tenant SaaS / billing | **Not included.** The schema supports multiple cities, but only one ("NovaCity") is seeded, and there's no billing/tenant-isolation layer. |

## Testing

```bash
cd backend && ./mvnw test
```

Unit tests cover the risk-scoring formulas and agent decision thresholds (Mockito);
an integration test spins up the full Spring context against the real Flyway-seeded
H2 database and exercises login, JWT validation, and role-based access control
end to end.

## A note on how this was built

This project was generated by Claude in a single extended session, directly from the
attached product brief. The Java backend could not be compiled inside that sandboxed
environment (no Maven Central network access), so while the code was written
carefully and cross-checked with static-analysis scripts (import resolution, entity/
repository/DTO method-call verification), **you should run `mvn clean install` (or
`./mvnw clean install`) as your first step** and treat any compiler error as a bug
report — it's the fastest way to get anything that slipped through fixed. The
frontend, by contrast, **was** built and type-checked successfully in-sandbox
(`npm run build` passes with zero errors) since the npm registry was reachable there.
